O ambiente do treino e o cano até o celular

Antes de qualquer rede neural, a bancada: o Python com o PyTorch, uma régua de velocidade e o caminho que leva os números do treino até o celular.

O que foi feito

  • Diagnóstico da máquina (o notebook, não o PC da RX 7600).
  • Ambiente virtual .venv e requirements.txt com o PyTorch para processador.
  • Medição de velocidade com o estudo (estudo/evolucao.py).
  • Dashboard: npm install, 299 testes passando, npm run dev abrindo.
  • O .env com a conta do treino no Supabase e o teste do cano com a demo do treino/nuvem.py.

Por quê

Decisão · treinar no processador

A rede tem 1.992 pesos e cada estufa é uma conta pequena. Mandar trabalho tão miúdo para uma placa de vídeo custa mais do que ela economiza. O plano já previa isso; a placa Intel (XPU) fica para um teste futuro.

Decisão · PyTorch "só CPU"

A versão padrão vem com CUDA (para placas NVIDIA) e baixa ~2 GB. A versão para processador baixa ~200 MB e faz a mesma conta aqui.

Decisão · chamar o Python do venv direto, sem "ativar"

O Windows deste notebook bloqueia scripts .ps1 (política padrão), e o Activate.ps1 é um deles. Em vez de mudar a configuração do Windows, os comandos chamam .venv\Scripts\python.exe, que tem o mesmo efeito.

Decisão · a senha da conta do treino

O Gabriel autorizou definir uma senha nova. Ela foi gerada aleatória direto no .env, sem aparecer na tela, e o Supabase recebeu só o hash bcrypt (o embaralhamento de mão única que o banco guarda), pelo SQL Editor. O .env não vai para o Git.

O que surpreendeu

Memória apertada

Com outras sessões abertas, o notebook ficou com ~2 GB livres e o Claude Code parou os processos em segundo plano (o servidor do dashboard e a demo). Antes de treinar à noite, fechar o que não for preciso.

A demo é um treino de mentira

O --demo só inventa números para testar o cano. Ele não tem simulador nem rede neural. O primeiro treino real é o do passo 04.

Como reproduzir

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe estudo/evolucao.py
.venv\Scripts\python.exe -m treino.nuvem --demo        # Ctrl+C para parar
.venv\Scripts\python.exe -m treino.nuvem --apagar demo-...
.venv\Scripts\python.exe -m unittest treino.test_nuvem
